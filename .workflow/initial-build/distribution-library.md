# Native distribution library

Implement `internal/distribution` as a reusable Go package independent of the CLI/server/bootstrap. This is a local development packet, not a Linear record. Own only that package, its tests, `go.mod`/`go.sum` dependency additions, and `docs/distribution.md`. Use module `orchard.local/orchard`, Go 1.24 or newer. Keep public APIs practical for later adapters, with context, explicit paths/configuration, typed inspection results, and machine-readable problems. Do not edit UI, CLI, server, existing planner, bootstrap, or Swift wrapper files.

Read architecture, upstream command reference, and distribution-packet.md. Every build, signing and export operation must refuse non-Linux at runtime. No macOS or hosted fallback. Use Linux for all tests and compilation. This packet's API is implemented now; do not replace working behavior with a permanent placeholder blocker.

## Private configuration and identity

Create/load a strict, bounded schema for private signing configuration at a caller-selected path outside projects. Write only regular files with private permissions and no symlink traversal or overwrite. Configuration references separate unencrypted PEM private key, PEM certificate, CMS mobileprovision, optional additional trusted root PEM and explicit metadata; never copy secrets into project files or return key contents/passwords. Typed public reports should omit private paths. Reject encrypted keys with a useful error; do not add a password-on-argv path. Confirm certificate validity and key public-key match with Go crypto, accepting usual RSA/ECDSA PKCS8/PKCS1/EC keys.

Use pinned `howett.net/plist v1.0.1` for binary/XML plists and `github.com/smallstep/pkcs7 v0.2.3` for CMS. Verify pins through module sums. Upstream pkcs7.Verify() verifies signed content but deliberately does NOT establish a trusted chain. Report signature integrity and trust separately. Verify the profile signature; if caller supplies roots, use VerifyWithChainAtTime at caller's current time. Never treat the embedded signer or a root shipped inside a profile as a trust anchor. Expose untrusted/no-roots explicitly, and make export require a verified chain against explicit operator trust roots. Do not label an arbitrary custom trust root 'Apple verified'. Explain how to obtain Apple PKI roots from the official website.

Inspect profile plist and identity: UUID/name/expiry/creation/team/application identifier, developer certificate DER membership by exact SHA256, entitlements, device list presence, ProvisionsAllDevices and get-task-allow. Store export requires matching non-wildcard bundle ID/team, current profile/certificate, no device list, no enterprise flag, get-task-allow false, matching signing certificate and key. Detect presence of empty device arrays too. Requested entitlements must be a compatible subset, including Apple wildcard patterns where valid; do not blindly copy profile-only wildcard entitlement values into the app. Reject unknown/unsupported entitlements with actionable diagnostics instead of changing them silently.

## Bundle / IPA inspection

Implement bounded regular-file input and safe archive checks. IPA inspection must reject absolute/traversal/duplicate/backslash names, symlink/special entries, suspicious compression sizes, too many entries, missing or multiple main Payload/*.app, and unsupported nested extensions. Read Info.plist (XML or binary), main executable Mach-O with arm64 iOS platform/minimum SDK metadata (LC_BUILD_VERSION or supported legacy load command), embedded profile, icon metadata, CFBundleIdentifier/Version/ShortVersionString, UIDeviceFamily. Compute IPA SHA256 using context-aware bounded reads. Report inspection facts and validation failures separately; checking structure is not Apple processing.

For export, accept real unsigned bundle input and output IPA path, explicit identity config, expected bundle/version/build, and caller-provided runner interface. Stage a safe bounded copy in a private temporary directory. Never alter source bundle, profile, key, certificate or an existing output. Reject symlinks and nonregular content; reject unsupported extensions/framework signing topology with a precise diagnostic. Remove existing main bundle signature ONLY from the staging copy before any asset compilation; xtool may add ad-hoc signatures. Run the AssetKit wrapper before signing when catalogs are present, using an explicit executable path and argv. Its interface will be coordinated by the manager; make the runner/action construction injectable rather than guessing flags. Require complete explicit iPhone/iPad/marketing PNG icon coverage and truthful SDK/build metadata; do not fabricate DTXcode/DTSDK fields. Validate catalog file containment.

The AssetKit bridge interface is now confirmed: `orchard-assets compile --catalog PATH.xcassets --app PATH.app --minimum-ios 17.0 --json`. It refuses existing `_CodeSignature`, `CodeResources`, or `embedded.mobileprovision`, so remove those only in the staging copy before calling it. It writes Assets.car, loose PNGs, and icon metadata into Info.plist.

Sign the staged bundle with actual zsign 1.1.2 contract: `zsign -k KEY.pem -c CERT.pem -m PROFILE.mobileprovision -e ENTITLEMENTS.plist -o STAGED_OUTPUT.ipa STAGED.app`. No shell invocation. Generated entitlements are private temporary data. The API exposes a redacted public plan, never logs private argv. Caller runner gets secret paths only internally. Verify output exists, is bounded, can be inspected, and matches expected identity/version/build/profile; atomically move to a previously absent destination. Return SHA256 receipt with honest signature/chain/structure facts. A synthetic zsign subprocess fixture is acceptable only as test coverage, clearly distinct from real Apple signing.

## Validation and phase output

Write meaningful tests with generated ephemeral certificate chains/CMS profiles and temporary bundles/ZIPs: valid trusted profile, untrusted signer, tampered CMS, wrong key/certificate/bundle/team, expiry, development/ad-hoc/enterprise profiles, binary plist, malformed and oversized inputs, archive traversal/symlinks/duplicates, unsupported topology, failed/missing signer output, unchanged source bundle, existing output preservation. No real Apple credentials or account calls. Report tests actually run on Linux. If the factory image lacks Go, use the official checksum-verified Linux tarball; do not run host builds.

Planning must list one product runtime target: platform `web`, flow `orchard-workspace`, artifacts `image` and `video`. This library's unit/subprocess tests are source checks; the parent performs the exact integrated application proof. End with committed implementation and precise limitations.
